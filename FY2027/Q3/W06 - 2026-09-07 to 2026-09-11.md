### Tuesday

Spent much of the day on AUTH-3268, the Jane Street report of a burst of bare HTTP 500s from api.pagerduty.com. Dug through Loki logs for the FE-LB and bff-public-api, then cross-checked with Datadog's Envoy metrics to rule out the sidecar. Found two short spikes hitting the whole bff-public-api fleet evenly, not just Jane Street, and traced it to an uncaught exception in AuthenticationDirectives.scala that swallows the real error. It bottoms out in a call to auth-service, which isn't our team's code, so I wrote up a handoff summary for that team and called it done on our end. Ticket's closed out.

Also fixed a long-standing annoyance with my knifeprod alias — it was leaving my shell in $HOME instead of the chef repo after running. Turned out to be oh-my-zsh's AUTO_PUSHD messing with the pushd/popd pair in the function. Rewrote knifestg, knifeprod, knifeeuprod, knifefedstg, and knifefedprod to share a helper that runs in a subshell instead, added a KNIFE_DEBUG flag for when I need to see what it's doing. While I was in there I also found that bundle exec knife is broken locally because of a Gemfile.lock bump for some CVEs (CORE-4623) — the .bundle cache still has old gems installed. Left that one alone for now, need to run bundle install at some point.

Merged the CLAUDE.md hierarchy distribution PR for CORE-4681. Also closed out CORE-4997, the wormly-sync CronJob fix to add activeDeadlineSeconds so a stuck Job can't wedge the schedule — PRs for that had been sitting for a bit.

Rest of the day was vulnerability ticket triage: moved the ops one to In Progress, infra and adminlb to Ready for Review, chef and chef-dr to In Review, and the two web-priv-lb ones are Blocked for now.

### Thursday

Picked back up the infra display work from yesterday, finally got the Chef staging key and Cloudsmith creds sorted so I could build and test locally instead of just eyeballing the diff. Finished CORE-5021, pushed the SSH column removal, opened PR #167, and it merged clean (a Copilot follow-up caught a CSS cache-buster mismatch). Moved on to CORE-5022, the Service-to-Role column swap. Nodes can carry multiple non-base roles, so I added a role helper in update.rb, wired up the new Roles summary row, and had to rebase after CORE-5021 landed on main. Opened PR #168 and ran the code-review skill against it, which caught two real bugs: pulling the visible Service cell broke the substring-based Service filter in infra.js, and duplicate role names were inflating the role counts. Fixed both and pushed a follow-up commit. Also reviewed PR #167 on its own and found host-page.eruby was still pointing at infra.css?v=7 after the cache-buster bump to v=8 on the main page, proposed the fix but held off applying it since it got rejected. PR #168 merged by end of day; Jira's still showing In Review for CORE-5022 even though it's in main, worth a manual nudge.

Rest of the day was back on the CORE-4968 Wiz pile. Worked through the remaining Python CVE batch: certifi, cryptography, urllib3, ansible, pyyaml, and a few more. Most turned out to be false positives. The OpenSSL CVEs in cryptography don't apply because Ubuntu's package is dynamically linked against system OpenSSL, not the vendored Rust build, and certifi's bundled cert file is dead code since Debian patches it to use the system CA store. Also chased down a scare where pro security-status said 771 packages were unavailable, turned out that was just from running it without sudo, ESM and FIPS are fine through April 2027. Closed out all 53 CVEs on that ticket with zero code changes needed and wrote up the full breakdown in a ticket comment. Also moved CORE-4922, another Wiz VM ticket, to In Progress.
